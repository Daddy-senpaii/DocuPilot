# 🚀 DocuPilot Deployment Guide

This guide explains how to deploy DocuPilot to **Render** using the included Blueprint (`render.yaml`), as well as general cloud deployment tips.

---

## 🌟 Deploying to Render (Recommended)

Render provides free and starter tiers for PostgreSQL, Docker web services, and Static Sites. The repository includes a `render.yaml` blueprint that deploys all three components together with connected environment variables.

### Components Deployed:
1. **`docupilot-db` (PostgreSQL Database)**
   - Pre-configured with PostgreSQL and `pgvector` extension support.
   - Automatically provisions credentials and passes the connection string to the backend.
2. **`docupilot-backend` (Go + Gin Web Service)**
   - Built via `backend/Dockerfile` with LibreOffice pre-installed for document conversion.
   - Automatically connects to `docupilot-db` and exposes `/health` and `/api/*`.
3. **`docupilot-frontend` (React + Vite Static Site)**
   - Automatically builds via `npm install && npm run build`.
   - Injects `VITE_API_BASE_URL` pointing to the deployed backend service.
   - Configured with SPA rewrite rules (`/* -> /index.html`).

---

### Step-by-Step Render Deployment:

1. **Push your code to GitHub:**
   Ensure the latest code with `render.yaml` is pushed to your GitHub repository:
   ```bash
   git push origin <your-branch>
   ```

2. **Open Render Dashboard:**
   - Go to [dashboard.render.com](https://dashboard.render.com/).
   - Click **New +** in the top navigation bar.
   - Select **Blueprint**.

3. **Connect Your Repository:**
   - Choose your `DocuPilot` repository.
   - Render will detect `render.yaml` automatically and display the three resources to be created:
     - `docupilot-db` (Database)
     - `docupilot-backend` (Web Service)
     - `docupilot-frontend` (Static Site)

4. **Provide Required Environment Variables:**
   - **`GEMINI_API_KEY`**: Enter your Google Gemini API key (from [Google AI Studio](https://aistudio.google.com/)). If left blank, DocuPilot runs in demo mode with deterministic mock responses.
   - `DATABASE_URL`: Automatically populated by Render from `docupilot-db`.
   - `JWT_SECRET`: Automatically generated by Render with high entropy.
   - `VITE_API_BASE_URL`: Automatically linked to the backend service hostname.

5. **Deploy:**
   - Click **Apply**.
   - Render will provision the database, build the backend Docker container, and compile the frontend.
   - Once complete, open your `docupilot-frontend.onrender.com` URL to use DocuPilot in production!

## 🛠️ Verification & Health Checks

Once deployed, verify the endpoints:
- **Backend Health Check:**
  ```bash
  curl https://<your-backend-subdomain>.onrender.com/health
  # Expected: {"status":"ok","time":"..."}
  ```
- **Database Initialization:**
  Check backend logs in the Render dashboard for:
  ```text
  Connecting to PostgreSQL at DATABASE_URL...
  Connected to PostgreSQL successfully.
  ```

## 🔐 Environment Variables Reference

| Variable | Service | Required | Description |
| :--- | :--- | :--- | :--- |
| `DATABASE_URL` | Backend | Optional | PostgreSQL connection string with pgvector (fallback: in-memory store) |
| `GEMINI_API_KEY` | Backend | Optional | Google Gemini API key for real-time document Q&A and embeddings |
| `GEMINI_MODEL` | Backend | Optional | Gemini model name (default: `gemini-1.5-flash`) |
| `JWT_SECRET` | Backend | Recommended | 32+ character secret for signing user authentication tokens |
| `PORT` | Backend | Auto-set | Listening port (Render provides `10000`, local defaults to `8080`) |
| `VITE_API_BASE_URL` | Frontend | Required in Prod | Base URL of deployed backend (e.g. `https://<backend>.onrender.com`) |
